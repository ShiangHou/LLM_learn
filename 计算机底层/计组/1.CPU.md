## CPU是什么

CPU就是中央处理器

本章我们需要知道的是，当我们写下1+1等于2的时候，后面的CPU是怎么执行的

这个流程是

可以把整个流程粗略理解为：

```
高级语言源代码
    ↓ 编译
机器语言程序 / 可执行文件
    ↓ 加载到内存
CPU 从内存读取指令
    ↓
使用寄存器暂存数据和地址
    ↓
执行运算、跳转、函数调用等操作
```

![image-20260613152242344](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260613152242344.png)



用 C 等高级语言写程序，编译为机器语言形式的可执行文件，程序运行时加载到内存，最后由 CPU 解释并执行



再明白这些之前，我们需要定义一些东西

1：程序是什么

答：计算机中的每一个动作和每一个指令

例如：

```c
int a;
a = 1 + 2;
printf("%d", a);
```

这个程序告诉计算机：

```
准备一个变量 a
计算 1 + 2
把结果存入 a
输出 a
```

所以程序不是一个抽象的“东西”，而是一连串具体动作的说明。

程序是什么构成的

答：指令+数据

例如：

```c
printf("你好");
```

其中：

```
printf 是指令
"你好" 是数据
```

再比如：

```c
a = 1 + 2;
```

这里：

```
加法、赋值是指令
1、2、a 是数据或数据存储位置
```

这点非常重要，因为后面 CPU 执行程序时，本质上就是不断处理：

```
从哪里取指令？
从哪里取数据？
把结果放到哪里？
下一条指令在哪里？
```

这样的流水线操作。

什么是机器语言？

答：CPU 可以直接识别并执行的语言。

和我们的C、C++、python、java不一样，

C、Java、Python 这些高级语言，CPU 不能直接执行。对于 C/C++ 这类语言，通常需要经过编译，转成机器语言后才能被 CPU 执行。

可以理解为：

```
人类容易读：C / Java / Python
CPU 容易读：机器语言
中间桥梁：编译器 / 解释器 / 虚拟机等
```

第一章主要关注的是：**程序变成机器语言后，CPU 如何执行它。**

正在运行的程序存储在哪里？

答：内存

硬盘上的程序不能直接运行。双击程序图标后，操作系统会把程序从硬盘复制到内存中，然后 CPU 才能读取并执行。

所以：

```
硬盘：长期保存程序
内存：运行时暂存程序和数据
CPU：执行内存中的程序
```

内存地址是什么？

答：内存中用来表示指令和数据存储位置的数值。

可以把内存想象成一排带编号的格子：

```
地址 0100：某条指令
地址 0101：某条指令
地址 0102：某个数据
地址 0103：某个数据
```

CPU 要读取内存中的内容，必须知道地址。

谁负责运行程序？

答：CPU

CPU 根据程序指令进行数据运算，并控制整个计算机。

## CPU的组成部分

4个部分组成，即寄存器 + 控制器 + 运算器 + 时钟

![image-20260613153012720](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260613153012720.png)

四个部分

###  寄存器

寄存器是 CPU 内部的小型存储区域，用来临时保存：

```
指令
数据
内存地址
运算结果
程序状态
```

你可以把寄存器理解为 CPU 手边的“草稿纸”。

CPU 不能每一步都直接从内存里慢慢取数据，所以它会把马上要用的数据先放进寄存器。寄存器非常快，CPU 执行机器语言时会频繁使用它。



> 所以说，寄存器是更靠近CPU的一块区域，是CPU直接运行程序的地方（再往外是内存）

### 控制器

控制器负责：

```
从内存中读取指令和数据
解释指令
根据指令结果控制整个计算机
```

这里的“控制”不要想得太玄，它主要是指除计算以外的协调工作，例如：

```
什么时候从内存读数据
什么时候向内存写数据
什么时候读取键盘输入
什么时候向显示器输出
什么时候访问磁盘
```

所以寄存器就是用来存储，控制器就是用来控制流程

### 计算器

运算器负责执行计算，例如：

```
加法
减法
比较
逻辑运算
移位运算
```

例如执行：

```
a = 1 + 2;
```

最终 CPU 内部就会进行类似：

```
把 1 放入某个寄存器
把 2 放入某个寄存器
由运算器执行加法
把结果 3 放回寄存器或内存
```

### 时钟

时钟负责给 CPU 提供节奏。

CPU 不是随意执行指令，而是按照时钟信号一步一步运行。主频越高，单位时间内时钟信号越多，理论上 CPU 可以执行更多操作。

例如 2GHz 可以粗略理解为：

```
每秒 20 亿次时钟信号
```

当然真实性能还会受指令复杂度、流水线、缓存、内存访问等因素影响，但第一章只需要先理解：

```
时钟信号是 CPU 执行动作的节拍器
```

## 内存

内存的特点是：

```
存储正在运行的程序和数据
每个字节都有地址
CPU 可以根据地址读取或写入数据
断电后内容会消失
```

这里要区分：

```
硬盘：长期保存，速度较慢
内存：运行时保存，速度较快，断电丢失
寄存器：CPU 内部，速度最快，容量很小
```

可以用一个层次图理解：

```
CPU 寄存器
    ↑ 最快、最小
内存
    ↑ 较快、较大
硬盘
    ↑ 较慢、最大、可长期保存
```

程序运行时的基本过程是：

```
1. 程序原本保存在硬盘中
2. 操作系统把程序复制到内存
3. CPU 根据内存地址读取指令
4. CPU 把数据放入寄存器处理
5. 处理结果写回寄存器、内存或输出设备
```

## CPU 是寄存器的集合体



机器语言层面的程序，很多操作都是围绕寄存器展开的。

也就是说，我们是把各种程序当作对象来去看的

书中用汇编代码举例：

```
mov eax, dword ptr [ebp-8]
add eax, dword ptr [ebp-0Ch]
mov dword ptr [ebp-4], eax
```

这几行大概表示：

```
把内存中的某个值复制到 eax 寄存器
把另一个内存中的值加到 eax
把 eax 中的结果写回内存
```

其中：

```
eax 是累加寄存器
ebp 是基址寄存器
```

这说明高级语言中的一句：

```
c = a + b;
```

编译成机器语言后，并不是 CPU 直接“理解 c = a + b”，而是变成了：

```
从内存取 a
放入寄存器
从内存取 b
与寄存器里的 a 相加
把结果写回内存
```

所以，从底层看，程序运行就是：

```
内存 ↔ 寄存器 ↔ 运算器 ↔ 寄存器 ↔ 内存
```

### 程序计数器

程序计数器是寄存器的一种，它是决定了程序的流程



我们前面说过，存储指令和数据是通过内存地址来进行的，



当os把程序从硬板中读取到内存里面，

地址 0100 是程序运行的开始位置。 Windows 等操作系统把程序从硬盘复制到内存后， 会将程序计数器（ CPU 寄存器的一种） 设定为  0100， 然后程序便开始运行。 CPU 每执行一个指令， 程序计数器的值就会自动加 1。 例如， CPU 执行 0100 地址的指令后， 程序计数器的值就变成了 0101（ 当执行的指令占据多个内存地址时， 增加与指令长度相应的数值）。 然后， CPU 的控制器就会参照程序计数器的数值， 从内存中读取命令并执行。 也就是说， 程序计数器决定着程序的流程。  

![image-20260624004557569](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260624004557569.png)

> 回到本身，程序计数器也是一种寄存器，即一种地址，所以这里是说是吧执行的指令（和数据）都按照流程存放到这个程序技术器中（也即某种地址）的意思。只不过这种地址是专门负责这个的
