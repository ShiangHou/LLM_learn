## 0. 本节课的核心主线

这节课表面上是在讲 GPU，但真正想讲的是：

> **为什么现代大模型离不开 GPU，以及为什么写高性能 ML 算法时，不能只看数学公式，还必须理解硬件的数据搬运方式。**

   - 什么是 memory-bound 和 compute-bound？
   - 为什么矩阵乘法很快，elementwise 操作反而可能慢？
   - 为什么矩阵维度是不是 64、128 的倍数会影响速度？
3. **FlashAttention 为什么能加速 attention？**
   - 它不是改变 attention 的数学结果；
   - 而是通过 tiling、fusion、online softmax、recomputation 减少显存读写。

## 2. 为什么大模型需要 GPU scaling？

课件先从 scaling law 讲起。

在语言模型里，很多时候只要增加 compute，模型性能就能按照比较稳定的规律提升。换句话说，**算力本身就是推动模型进步的重要因素**。

但是传统 CPU 时代的 scaling 已经遇到瓶颈。

早期芯片性能提升靠的是 **Dennard scaling**：

> 晶体管变小，电压降低，频率提高，功耗密度不变。

这让 CPU 在很长一段时间里可以持续变快。但大约 2000 年之后，这条路逐渐走不通了。频率不能无限提高，功耗和散热成了限制。

于是现代 AI 的 compute scaling 更多依赖：

- 大规模并行；
- GPU 数量增加；
- Tensor Core；
- 低精度计算；
- 更好的 kernel；
- 更好的分布式训练。

课件里非常关键的一句话是：

> **There is no LLM scaling without GPU scaling.**

可以理解为：

> 没有 GPU 的并行计算能力，就没有今天的大语言模型规模。

## 3. CPU 和 GPU 的核心区别

![image-20260606113506188](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606113506188.png)





### 3.1 CPU：少量强线程，优化 latency

CPU 的设计目标是：

> 让单个任务尽快完成。

所以 CPU 有：

- 强控制逻辑；
- 大缓存；
- 分支预测；
- 乱序执行；
- 高单核性能。

CPU 很适合：

- 操作系统；
- 数据库控制逻辑；
- Python 主程序；
- 分支很多的任务；
- 复杂但并行度不高的任务。

你可以把 CPU 理解为：

> 几个很聪明、很强的专家。

每个专家能处理复杂任务，但专家数量有限。

------

### 3.2 GPU：大量弱线程，优化 throughput

GPU 的设计目标是：

> 不追求单个线程最快，而追求单位时间内总共处理多少数据。

所以 GPU 有：

- 很多 ALU；
- 很多 SM；
- 海量线程；
- 较少控制逻辑；
- 较弱分支处理能力；
- 非常适合规则并行计算。

GPU 像：

> 一大群工人，每个人能力不强，但能同时做大量重复工作。

这特别适合深度学习，因为神经网络主要是：

- 矩阵乘法；
- 向量加法；
- elementwise 操作；
- reduction；
- softmax；
- normalization。

这些操作都具有很强的数据并行性。



这里也就是李沐说的，控制弱，但是呢，直接怼人力，然后并行运算，"core“很多



## 4. GPU 的执行单元：SM 和 SP

课件接下来讲 GPU 的基本组成。

![image-20260606113742420](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606113742420.png)

### 4.1 SM：Streaming Multiprocessor

GPU 里有很多个 **SM**，全称是 **Streaming Multiprocessor**。

SM 可以理解为 GPU 里的一个“计算小工厂”。

每个 SM 可以独立执行一个或多个 thread block。比如讲义中提到 GA100 Full GPU 有 128 个 SM。

SM 越多，理论上可以同时执行的 block 越多，吞吐能力越强。



------

### 4.2 SP：Streaming Processor

每个 SM 内部又有很多更小的计算单元，叫 **SP**，也就是 streaming processor。

这些 SP 执行具体的线程计算。

所以层级大概是：

```
GPU
 ├── SM 0
 │    ├── SP / CUDA cores
 │    ├── registers
 │    ├── shared memory
 │    └── warp scheduler
 ├── SM 1
 ├── SM 2
 └── ...
```

你可以粗略理解为：

- GPU 是整个工厂；
- SM 是一个车间；
- SP / CUDA core 是车间里的工位；
- thread 是被分配到工位上的任务。

## 5. GPU 的内存层级

这节课非常强调 memory hierarchy。

![image-20260606113926447](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606113926447.png)

GPU 不是所有内存访问都一样快。越靠近 SM 的内存越快，但容量越小、成本越高。

大致层级是：

```
Registers
  ↓
Shared Memory / L1 Cache
  ↓
L2 Cache
  ↓
Global Memory / HBM
```

------

### 5.1 Register

Register 是每个线程自己的私有存储。

特点：

- 最快；
- 容量最小；
- 每个 thread 独享；
- 适合放临时变量。

例如 CUDA kernel 中一个线程内部的局部变量，很多时候会放在 register 里。

------

### 5.2 Shared Memory

Shared memory 位于 SM 内部。

特点：

- 比 global memory 快很多；
- 一个 block 内的所有线程可以共享；
- 不同 block 之间不能直接共享；
- 容量有限。

Shared memory 是后面 **tiling** 的核心。

因为如果多个线程会重复使用同一批数据，就可以先把数据从 global memory 搬到 shared memory，然后在 block 内反复使用。

------

### 5.3 L1 / L2 Cache

L1 通常靠近 SM，L2 是整个 GPU 共享的片上缓存。

它们比 HBM 快，但程序员对 cache 的控制通常没有 shared memory 那么直接。

------

### 5.4 Global Memory / HBM

Global memory 就是我们常说的 GPU 显存。

比如：

- A100 40GB / 80GB HBM；
- H100 80GB HBM；
- L20 48GB GDDR6。

特点：

- 容量大；
- 带宽高；
- 但延迟远高于 register/shared memory。

这节课最重要的思想之一是：

> **不要频繁把中间结果写回 global memory。**

因为 global memory 再快，也比不上片上 memory。

这个和那个CPU里面的是不是差不多，L1L2L3寄存器，越靠近里面的它的存储就越快

## 6. GPU 的执行模型：Thread、Block、Warp

课件讲了三个关键执行概念：

1. thread；
2. block；
3. warp。
4. ![image-20260606114611646](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606114611646.png)

------

### 6.1 Thread：最小的逻辑执行单元

CUDA 编程中，你会写很多线程。

每个 thread 负责处理一小份数据。

比如对一个长度为 n 的向量做 ReLU：

```
y[i] = max(0, x[i])
```

就可以让第 i 个 thread 处理第 i 个元素。

------

### 6.2 Block：一组 thread

多个 thread 组成一个 block。

一个 block 会被调度到一个 SM 上执行。

block 内的线程可以：

- 共享 shared memory；
- 使用同步操作，比如 `__syncthreads()`；
- 协作完成一个 tile 的计算。

不同 block 之间一般不能直接同步。如果需要跨 block 传递信息，通常要读写 global memory。

这也是为什么课件说：

> 跨 block 的信息需要通过 global memory，比较慢。

------

### 6.3 Warp：GPU 实际调度的基本单位

虽然我们写 CUDA 时面对的是 thread，但 GPU 硬件调度时通常以 **warp** 为单位。

一个 warp 通常包含：

```
32 个连续编号的 threads
```

一个 warp 内的线程执行同一条指令，只是作用在不同数据上。

这就是 **SIMT**：

> Single Instruction, Multiple Threads.

也就是：

```
同一条指令
不同线程
不同数据
```

比如一个 warp 同时执行：

```
y[i] = x[i] + 1
```

只是每个 thread 的 i 不同。

## 7. SIMT 模型的优势和问题

### 7.1 优势

SIMT 对深度学习非常合适，因为神经网络操作通常很规则：

- 每个元素做同样的加法；
- 每个 token 做同样的矩阵乘法；
- 每个 attention head 做类似计算。

所以 GPU 可以让成千上万个线程一起执行相同指令。

------

### 7.2 问题：Control Divergence

如果一个 warp 内部出现分支：

```
if (threadIdx.x < 4) {
    A;
    B;
} else {
    X;
    Y;
}
Z;
```

那么有些线程要走 if，有些线程要走 else。

但 warp 的执行模型要求大家执行同一条指令，所以 GPU 通常会：

1. 先让满足 if 的线程执行 A、B；
2. 不满足的线程暂时 mask 掉；
3. 再让 else 分支的线程执行 X、Y；
4. 最后一起执行 Z。

这叫 **control divergence**。

它的后果是：

> 分支越不一致，warp 的并行效率越低。

所以 GPU 不喜欢复杂分支，尤其不喜欢一个 warp 内部线程走不同路径。

------

## 8. GPU 和 TPU 的关系

课件中间简单提到 TPU。

从高层看，GPU、TPU 和其他 AI accelerator 有相似结构：

- 轻量控制单元；
- 大矩阵乘法单元；
- 快速片上内存；
- 高带宽外部内存。

区别主要在：

1. **并行模型不同**
   - GPU 有 warp；
   - TPU 通常更偏向 systolic array / matrix unit。
2. **矩阵乘法单元组织方式不同**
   - GPU 有更多 SM；
   - TPU 有较少但更大的矩阵乘法单元。
3. **互联方式不同**
   - 多 GPU、多 TPU 的通信拓扑不同；
   - 这部分会在 parallelism lecture 里继续讲。

这里你只需要记住：

> GPU 和 TPU 本质上都是为大规模矩阵计算和高吞吐数据流设计的 accelerator。

## 9. GPU 模型的优势

课件总结了 GPU 的几个优势。

### 9.1 容易扩展 hard workloads

如果任务有大量并行性，比如矩阵乘法，GPU 可以通过增加更多 SM 来提升吞吐。

这也是为什么 GPU 架构每代都在增加：

- SM 数量；
- Tensor Core 数量；
- HBM 带宽；
- 片上缓存。

------

### 9.2 SIMT 模型相对容易编程

相比纯硬件加速器，GPU 还是比较通用的。

程序员可以写类似 C/C++ 的 CUDA kernel，然后把很多 thread 映射到数据上。

当然，“容易”是相对的。写能跑的 CUDA 不难，写非常快的 CUDA 很难。

------

### 9.3 Thread 很轻量

GPU thread 的创建、切换、隐藏延迟方式和 CPU thread 不一样。

GPU 可以同时维护大量线程。当一些线程在等待内存时，调度器可以切换到其他 ready 的 warp 执行。

这叫 **latency hiding**。

所以 GPU 不是通过让 memory latency 变小来解决问题，而是通过：

> 用大量线程把等待时间盖住。

------

# Part 1 小结：GPU 是什么

到这里，课程第一部分的核心结论是：

1. GPU 是 massively parallel architecture；
2. GPU 适合大量线程执行同样指令；
3. GPU 的计算能力，尤其矩阵乘法能力，增长很快；
4. 但是 memory scaling 没有 compute scaling 快；
5. 所以写 GPU 高性能程序，必须尊重 memory hierarchy。

最重要的一句话是：

> **GPU 快的前提是：计算规则、并行度高、数据搬运少、内存访问模式好。**

## 10. 为什么 GPU 性能很复杂？

课件第二部分开始讲一个现象：

> 即使是最简单的 square matmul，不同矩阵大小下性能也会非常复杂。

你可能直觉以为：

```
矩阵越大 → 计算越多 → 越慢
```

但 GPU 上并不总是这样。

有时候矩阵稍微变大，反而更快。

原因包括：

- tile size 是否整除矩阵维度；
- memory 是否对齐；
- warp 是否 coalesced；
- Tensor Core 是否能充分利用；
- SM 是否被均匀填满；
- kernel 是否 memory-bound。

所以 GPU 性能不是只看 FLOPs 数量，而是看：

> **FLOPs + memory access + hardware utilization**

## 11. Roofline Model

课件引入 **roofline model**，这是理解 GPU 性能的核心工具。

Roofline model 想回答：

> 一个程序的性能上限到底被什么限制？

它通常用这个公式理解：

```
实际性能 ≤ min(峰值计算性能, 内存带宽 × arithmetic intensity)
```

其中：

```
arithmetic intensity = FLOPs / bytes moved
```

也就是：

> 每搬运 1 byte 数据，能做多少次浮点运算。

------

### 11.1 Compute-bound

如果一个操作 arithmetic intensity 很高，说明它搬一点数据能做很多计算。

这种情况下性能主要受限于 GPU 计算能力。

典型例子：

- 大矩阵乘法；
- 大 batch GEMM；
- Transformer MLP 中的大 Linear。

这类操作叫 **compute-bound**。

------

### 11.2 Memory-bound

如果一个操作 arithmetic intensity 很低，说明它搬很多数据，但只做一点点计算。

这种情况下性能主要受限于内存带宽。

典型例子：

- ReLU；
- dropout；
- elementwise add；
- layernorm；
- softmax；
- small tensor 操作。

这类操作叫 **memory-bound**。

------

### 11.3 对大模型训练的意义

Transformer 中既有 compute-bound 操作，也有 memory-bound 操作。

例如：

| 操作                   | 主要瓶颈           |
| ---------------------- | ------------------ |
| Linear / Matmul        | 通常 compute-bound |
| Attention score matmul | 通常 compute-bound |
| Softmax                | 常常 memory-bound  |
| LayerNorm              | memory-bound       |
| Dropout                | memory-bound       |
| Elementwise add        | memory-bound       |

所以优化大模型性能时，不能只优化 matmul。很多时间浪费在 memory-bound 的小操作上。

这就是为什么：

- FlashAttention 很重要；
- fused layernorm 很重要；
- fused optimizer 很重要；
- torch.compile 可能有帮助；
- activation checkpointing 有帮助；
- kernel launch overhead 也需要关注。

## 13. Control Divergence 是什么？

GPU 是 SIMT 模型。

一个 warp 内的 32 个线程应该执行同一条指令。

如果大家走不同分支，就会出现 divergence。

例如：

```
if (x > 0) {
    y = x;
} else {
    y = 0;
}
```

如果一个 warp 中：

- 16 个线程 x > 0；
- 16 个线程 x <= 0；

GPU 不能让两组线程真正同时跑不同指令，而是要分两次执行。

这会导致：

> warp 内有些线程在某些时间是 inactive 的。

所以性能下降。



这个之前warp里面说过

![image-20260606134456514](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606134456514.png)

------

## 14. Control Divergence 的优化直觉

GPU 上要尽量避免：

- 一个 warp 内线程走不同分支；
- 分支逻辑很复杂；
- while 循环次数差异很大；
- 数据依赖导致线程执行路径不一致。

在深度学习里，大多数 tensor operation 比较规则，所以 control divergence 通常不是最大瓶颈。

但在一些场景里会很重要：

- 稀疏计算；
- MoE routing；
- dynamic shape；
- beam search；
- token-level 条件分支；
- ragged tensor；
- 图神经网络。

# Trick 1：Low Precision Computation

------

## 15. 低精度为什么能加速？

课件里一句话非常关键：

> If you have fewer bits, you have fewer bits to move.

低精度有两个直接好处。

### 第一，减少内存搬运

比如：

| 精度 | 每个数占用 |
| ---- | ---------- |
| FP32 | 4 bytes    |
| FP16 | 2 bytes    |
| BF16 | 2 bytes    |
| INT8 | 1 byte     |
| INT4 | 0.5 byte   |

如果模型参数、激活、中间结果用更少 bit 表示，就可以减少：

- HBM 读写；
- cache 压力；
- 通信量；
- 显存占用。

------

### 第二，使用专门硬件

现代 NVIDIA GPU 有 Tensor Core。

Tensor Core 对低精度矩阵乘法做了专门加速，比如：

- FP16；
- BF16；
- TF32；
- FP8；
- INT8。

所以低精度不仅减少 memory traffic，还能提升 matmul 吞吐。

------

## 16. 低精度如何提高 arithmetic intensity？

课件用 ReLU 举例：

```
x = max(0, x)
```

对每个元素来说：

- 读一次 x；
- 写一次结果；
- 做一次比较或简单操作。

如果是 FP32：

```
read 4 bytes + write 4 bytes = 8 bytes
```

如果是 FP16：

```
read 2 bytes + write 2 bytes = 4 bytes
```

计算量差不多，但数据搬运减少一半。

因此对于 memory-bound 操作，低精度会明显改善性能。

注意：课件在这个例子里用的是 “bytes per FLOP” 的视角，而 roofline 常用 “FLOPs per byte”。两者互为倒数。核心意思一样：

> 数据越小，每次计算需要搬运的数据越少。

------

## 17. Mixed Precision

现代训练通常不是全部用 FP16，而是 mixed precision。

比如：

- 激活用 BF16；
- 权重用 BF16；
- 梯度可能用 BF16；
- 某些累加用 FP32；
- optimizer states 可能用 FP32；
- 推理时可能量化到 INT8 / INT4。

为什么需要 mixed precision？

因为低精度虽然快，但可能有：

- overflow；
- underflow；
- rounding error；
- 训练不稳定。

所以一些对数值稳定性敏感的操作仍然可能需要高精度，比如：

- loss accumulation；
- softmax 部分统计；
- optimizer update；
- normalization 统计量。

------

## 18. Tensor Core 的意义

Tensor Core 是专门的矩阵乘法电路。

普通 CUDA core 做通用浮点运算，而 Tensor Core 特别适合做：

```
D = A @ B + C
```

尤其是小块矩阵乘法。

这就是为什么现代 GPU 上 matmul 的 TFLOPs 远高于普通非矩阵 FLOPs。

课件强调：

> Matmuls are more than 10x faster than other floating point ops.

这对 LLM 非常重要，因为 Transformer 的主要计算都可以转成 matmul：

- Q projection；
- K projection；
- V projection；
- output projection；
- FFN up projection；
- FFN down projection；
- attention score；
- attention value aggregation。

所以可以说：

> Transformer 是一种非常适合 GPU Tensor Core 的模型结构。

# Trick 2：Operator Fusion

------

## 19. 为什么需要 operator fusion？

![image-20260606142516653](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606142516653.png)

课件用一个工厂类比：

- memory 像仓库；
- compute 像工厂；
- 数据从仓库搬到工厂加工；
- 加工完再搬回仓库。

如果每个小操作都单独启动一个 CUDA kernel，就会发生：

```
读 global memory
计算一点点
写回 global memory
再读 global memory
再计算一点点
再写回 global memory
...
```

这非常浪费。

Operator fusion 的核心是：

> 把多个小操作合并到一个 kernel 里，中间结果不写回 global memory。

------

## 20. 例子：sin²x + cos²x

课件举了一个例子：

```
y = sin(x) ** 2 + cos(x) ** 2
```

朴素情况下可能有多个操作：

1. `sin(x)`
2. `sin(x) ** 2`
3. `cos(x)`
4. `cos(x) ** 2`
5. add

如果每一步都是一个 CUDA kernel，那么每一步都要：

- 从 HBM 读 x 或中间结果；
- 计算；
- 写回 HBM。

但实际上，中间结果完全可以留在 register 里，不需要反复写回显存。



![image-20260606142602615](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606142602615.png)

------

![image-20260606142809125](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606142809125.png)



## 21. Fusion 的效果

Fusion 之后可以变成一个 kernel：

```
读 x 一次
在 register 中计算 sin、cos、平方、加法
写 y 一次
```

这样减少了：

- global memory read；
- global memory write；
- kernel launch overhead；
- 中间 tensor materialization。

这对 memory-bound 操作非常有效。

------

## 22. PyTorch 中的 fusion

课件提到，简单的 fusion 可以由编译器自动完成，例如：

```
torch.compile
```

背后可能涉及：

- TorchInductor；
- Triton；
- nvFuser；
- CUDA graph；
- kernel codegen。

但是不是所有 fusion 都能自动完成。

复杂操作，比如 FlashAttention，需要专门设计 kernel。

------

## 23. 大模型中的 fusion 例子

常见 fused kernel 包括：

- fused LayerNorm；
- fused RMSNorm；
- fused bias + GELU；
- fused dropout + add + norm；
- fused AdamW optimizer；
- fused attention；
- fused cross entropy。

这些优化的共同点是：

> 尽量避免把中间结果写回 HBM。

![image-20260606142839816](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606142839816.png)

我来一句话总结，这个就是把这些多个memory和compute之间反复操作的弄到一块来就行



# Trick 3：Recomputation

------

## 24. Backpropagation 为什么要存 activation？

训练神经网络时，forward 会产生很多中间激活值。

Backward 需要这些激活值来计算梯度。

所以朴素训练会保存大量 activation。

例如一个简单网络：

```
x -> layer1 -> a1 -> layer2 -> a2 -> layer3 -> out
```

反向传播时，需要 a1、a2 等中间值。

![image-20260606143248418](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606143248418.png)



------

## 25. 保存 activation 为什么贵？

![image-20260606143326953](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606143326953.png)

保存 activation 有两个成本：

### 第一，显存占用

大模型训练中，activation 可能占用非常多显存。

尤其是：

- batch size 大；
- sequence length 长；
- hidden size 大；
- layer 数多。

Transformer 训练里，activation memory 往往是显存大头之一。

------

### 第二，读写显存成本

不仅要存下来，backward 时还要读回来。

所以它增加了 HBM traffic。

课件用三层 sigmoid 举例，说明如果保存每一层中间结果，会产生很多次 memory read/write，而计算本身很少。

这种情况下，瓶颈不是 sigmoid 计算，而是中间 activation 的读写。

------

## 26. Recomputation 的思想

![image-20260606143412366](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606143412366.png)

Recomputation 的想法很反直觉：

> 不保存所有 activation，backward 需要时重新算。

也叫：

- activation checkpointing；
- gradient checkpointing；
- rematerialization。

它做的是 trade-off：

```
少存 activation
↓
节省显存和 HBM 读写
↓
但 backward 时多做一些计算
```

------

## 27. 为什么重新计算可能更优？

因为现代 GPU 上：

> 计算越来越便宜，内存访问越来越贵。

如果重新算一次 activation 的计算成本小于保存和读取 activation 的内存成本，那么 recomputation 就是划算的。

这也是课件中说：

> Throwing away computation can actually be optimal.

也就是：

> 扔掉已经算过的东西，之后重新算，反而可能是最优选择。

------

## 28. 大模型训练中的 recomputation

你在训练大模型时经常会看到参数：

```
gradient_checkpointing=True
activation_checkpointing=True
recompute=True
```

它们就是这个思想。

例如训练 Qwen、LLaMA、Mistral 时，如果不开 checkpointing，显存可能直接 OOM。

开了以后：

- 显存占用下降；
- 可以用更长 sequence length；
- 可以用更大 batch size；
- 但训练速度会慢一些。

所以这是：

> 用时间换空间。

但从 GPU 性能角度看，有时不只是省显存，也可能减少 memory traffic，从整体上更优。

# Trick 4：Memory Coalescing

------

## 29. DRAM 的 burst mode

![image-20260606143614675](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606143614675.png)

课件接下来讲 global memory 访问。

DRAM 不是每次只读一个字节或一个 float。

它通常以 **burst mode** 读取一整段连续内存。

这意味着：

> 如果你访问一个地址，硬件往往会顺带读出这个地址附近的一段连续数据。

所以 GPU 喜欢连续访问。



**（这个以及后面的和李沐讲的是一样的，就是说我的一个矩阵存储是连续存储的，如果我横着读，那么就很舒服，如果我想按列去读，那么前面读的在读后面的时候就没有用）**

------

## 30. 什么是 memory coalescing？

![image-20260606144938969](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606144938969.png)



一个 warp 有 32 个线程。

如果这 32 个线程同时访问 global memory，而且访问地址是连续或落在同一个 memory burst 区间内，那么这些访问可以被合并成少量 memory transaction。

这叫：

> **coalesced memory access**

如果访问地址很分散，就需要很多 memory transaction，性能会很差。

------

## 31. Coalesced vs non-coalesced

理想情况：

```
thread 0 -> x[0]
thread 1 -> x[1]
thread 2 -> x[2]
...
thread 31 -> x[31]
```

这就是连续访问。

糟糕情况：

```
thread 0 -> x[0]
thread 1 -> x[1024]
thread 2 -> x[2048]
...
```

这就是 stride 很大的访问。

后者会浪费大量内存带宽。

（这个说的还是李沐说的那个）

------

## 32. 矩阵乘法中的 coalescing

对于 row-major 矩阵，连续地址通常沿着行方向排列。

但是是否 coalesced 不只取决于矩阵存储格式，还取决于：

> 相邻 thread 访问的是不是相邻地址。

如果 thread mapping 不好，即使矩阵本身 row-major，也可能导致 warp 内线程跨行或跨列跳跃访问。

所以高性能 kernel 会非常关注：

- thread 到矩阵元素的映射；
- memory layout；
- stride；
- alignment；
- vectorized load；
- shared memory layout。

![image-20260606150032762](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606150032762.png)

------

## 33. 为什么这对大模型重要？

大模型中很多 tensor 是多维的，例如：

```
[batch, seq_len, hidden]
[batch, num_heads, seq_len, head_dim]
```

不同 layout 会影响性能。

比如 attention 中，有时需要 reshape、transpose、permute。

如果这些操作导致数据不连续，后续 kernel 可能变慢。

所以你经常会看到：

```
x = x.contiguous()
```

它的意义就是重新整理内存，让数据连续。

但注意：`contiguous()` 本身也会产生一次 memory copy，所以不能乱用。

# Trick 5：Tiling

------

## 34. Tiling 是什么？

![image-20260606150301397](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606150301397.png)



Tiling 是这节课最重要的优化技术。

它的核心思想是：

> 把大矩阵切成小块 tile，把 tile 加载到 shared memory，然后在 shared memory 中重复使用。

为什么要这么做？

因为 global memory 慢，而 shared memory 快。

如果一个数据会被重复用很多次，不应该每次都从 global memory 读。

------

## 35. 朴素矩阵乘法的问题

考虑：

```
C = A @ B
```

其中：

```
C[i, j] = sum_k A[i, k] * B[k, j]
```

朴素做法中，每计算一个 C[i, j]，都要读取：

- A 的一行；
- B 的一列。

但相邻的 C 元素会重复使用 A 和 B 的部分元素。

如果每次都从 global memory 读，会产生大量重复访问。



![image-20260606150341261](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606150341261.png)

------

## 36. Tiling 的做法



![image-20260606150359104](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606150359104.png)

把 A、B、C 切成小块。

例如：

```
A_tile: T x T
B_tile: T x T
C_tile: T x T
```

步骤大概是：

1. 一个 block 负责计算 C 的一个 tile；
2. 把 A 的一个 tile 从 global memory 读到 shared memory；
3. 把 B 的一个 tile 从 global memory 读到 shared memory；
4. block 内线程协作计算 partial sum；
5. 继续加载下一个 tile；
6. 累加结果；
7. 最后把 C_tile 写回 global memory。

------

## 37. Tiling 的优势

主要有两个。

### 第一，减少 global memory 访问

如果没有 tiling，一个 A 元素可能会被从 global memory 读很多次。

有了 tiling，A 和 B 的 tile 被读入 shared memory 后，可以被多次复用。

课件给出的结论是：

> tiled matrix multiply 可以把 global memory access 降低约 T 倍。

这里 T 是 tile size。

------

### 第二，改善 coalescing

如果 tile 的加载方式设计得好，可以让 warp 内线程进行连续访问。

这样可以提高 memory coalescing，减少 memory transaction。

所以 tiling 同时解决：

- 重复读取；
- 非连续访问；
- shared memory reuse；
- Tensor Core tile shape 匹配。

------

## 38. Tiling 的复杂性

Tiling 不是随便选一个 tile size 就行。

课件提到几个影响因素：

1. coalesced memory access；
2. shared memory size；
3. matrix dimension divisibility。
4. ![image-20260606151031781](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151031781.png)

------

### 38.1 Tile size 可能不能整除矩阵大小

假设 tile size 是 128。

如果矩阵维度是 256，就刚好分成两个 tile。

但如果矩阵维度是 257，就需要三个 tile，其中最后一个 tile 大部分是空的。

这会导致：

- 计算资源浪费；
- thread 空转；
- SM 利用率下降。

所以矩阵维度是否是 tile size 的倍数非常重要。

------

### 38.2 Shared memory 容量有限

tile 太大，会放不进 shared memory。

tile 太小，reuse 不充分，global memory 访问减少不明显。

所以 tile size 要在下面几个目标之间平衡：

- tile 足够大，方便复用；
- tile 不能太大，否则 shared memory 不够；
- tile shape 要适配 Tensor Core；
- tile shape 要适配 warp 和 block；
- tile shape 最好能整除矩阵维度。

------

### 38.3 Memory alignment

![image-20260606151050913](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151050913.png)

即使 tile size 合理，如果内存地址不对齐，也可能导致访问效率低。

课件中展示了 aligned layout 和 unaligned layout 的区别。

aligned layout 可以让一个 tile 对应一个整齐的 burst section。

unaligned layout 可能需要跨多个 burst section，产生更多 memory transaction。

所以 GPU 喜欢：

```
维度是 8 / 16 / 32 / 64 / 128 的倍数
```

具体取决于数据类型、Tensor Core、kernel 实现和硬件架构。

# Matrix Mystery：为什么矩阵变大反而更快？

------

## 39. Karpathy 的例子

课件引用了 Karpathy 的一个观察：

> nanoGPT 中把 vocab size 从 50257 增加到 50304，训练反而快了很多。

这听起来很反直觉。

因为 vocab size 变大，embedding matrix 和 output projection 都变大了，理论计算量增加了。

但速度反而更快。

原因是：

```
50304 更接近 64 的倍数
```

它更适合 GPU 的 tile、alignment、Tensor Core。

![image-20260606151238222](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151238222.png)

------

## 40. 原因一：Tiling alignment

![image-20260606151249835](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151249835.png)



如果矩阵维度刚好能被 tile size 整除，GPU 可以高效分块。

如果不能整除，就会出现边缘 tile，大量 thread 做无效工作。

例如：

```
N = 256
tile size = 128
```

刚好两个 tile。

但：

```
N = 257
tile size = 128
```

需要三个 tile，最后一个 tile 只有很少有效元素。

这会显著降低 utilization。

------

## 41. 原因二：Wave Quantization

![image-20260606151306461](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151306461.png)



课件还讲了 **wave quantization**。

GPU 有固定数量的 SM。

假设一个 kernel 总共有 98 个 tile，而 GPU 有 108 个 SM。

那么一次 wave 就可以执行所有 tile，但有些 SM 会空闲。

如果总共有 120 个 tile，108 个 SM 第一轮执行 108 个，第二轮只剩 12 个 tile，很多 SM 空闲。

这就会导致周期性的性能波动。

所以性能不仅取决于 tile 是否整除矩阵维度，还取决于：

```
tile 数量和 SM 数量的匹配关系
```

这解释了为什么 matmul 性能曲线可能有周期性波动，而不是平滑增长。

------

## 42. 对模型设计的启发

这解释了为什么模型配置常常喜欢这些数字：

```
hidden_size = 4096, 5120, 6144, 8192
intermediate_size = 11008, 14336, 28672
head_dim = 64, 128
vocab_size padding 到 64 或 128 的倍数
```

这些不是随便选的，而是为了适配：

- Tensor Core；
- memory alignment；
- tiling；
- warp；
- SM scheduling。

所以做大模型系统时，模型结构也要考虑硬件友好性。

# Part 3：用这些知识理解 FlashAttention

------

## 43. 普通 Attention 的计算

![image-20260606151425309](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151425309.png)

Transformer attention 的核心是：

```
S = QK^T
P = softmax(S)
O = PV
```

其中：

- Q 是 query；
- K 是 key；
- V 是 value；
- S 是 attention score；
- P 是 softmax 后的 attention probability；
- O 是输出。

如果 sequence length 是 n，那么 S 和 P 都是：

```
n x n
```

这会带来严重问题。

------

## 44. 标准 attention 的问题

标准 attention 通常会显式 materialize attention matrix：

```
S = QK^T
P = softmax(S)
O = PV
```

也就是说：

1. 计算 S；
2. 把 S 写到 HBM；
3. 从 HBM 读 S 做 softmax；
4. 写 P 到 HBM；
5. 再读 P 和 V；
6. 计算 O。

问题是：

> attention matrix 太大，而且中间结果频繁读写 HBM。

当 sequence length 很长时，n² 矩阵非常大。

例如：

```
seq_len = 4096
attention matrix = 4096 x 4096
```

每个 head 都有这么大的 score matrix。

所以标准 attention 的瓶颈不只是 FLOPs，而是 HBM memory traffic。

------

## 45. FlashAttention 的核心思想

FlashAttention 并没有改变 attention 的数学结果。

它计算的是 exact attention，不是近似 attention。

它真正改变的是：

> 计算顺序和内存访问方式。

具体来说，FlashAttention 使用：

1. tiling；
2. fusion；
3. online softmax；
4. recomputation。

目标是：

> 避免把完整的 attention matrix 写入 HBM。

------

## 46. FlashAttention 的 tiling

![image-20260606151458465](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151458465.png)



FlashAttention 把 Q、K、V 切成 block。

它不是一次性计算完整的：

```
QK^T
```

而是 tile by tile 地计算局部 score。

例如：

```
Q block 与 K block 相乘
得到一个局部 S block
```

然后马上对这个 block 参与 softmax 和 V 加权，而不是把完整 S 保存下来。

------

## 47. 关键问题：softmax 怎么分块算？

![image-20260606151556103](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151556103.png)



普通 softmax 是：

```
softmax(x_i) = exp(x_i) / sum_j exp(x_j)
```

它有一个问题：

> 你需要看到整行所有元素，才能知道 denominator。

为了数值稳定，通常还会写成：

```
softmax(x_i) = exp(x_i - m) / sum_j exp(x_j - m)
```

其中：

```
m = max_j x_j
```

也就是说，softmax 需要整行的 max 和 sum。

这看起来和 tiling 矛盾。

因为 tiling 是一次只看一块。

------

## 48. Online Softmax

FlashAttention 使用 **online softmax**。

它可以一边扫描 tile，一边维护：

1. 当前最大值 m；
2. 当前归一化分母 l；
3. 当前 partial output。

当新的 tile 到来时，如果发现新的 max 更大，就用一个缩放因子修正之前累计的结果。

这就是课件说的：

> incrementally update the max, and set up a telescoping sum.

简单说就是：

> 不需要一次看到完整 attention row，也能正确计算全局 softmax。

这一步是 FlashAttention 能 tile-by-tile 计算 exact attention 的关键。



![image-20260606151715262](https://cdn.jsdelivr.net/gh/ShiangHou/markdown_image/img/image-20260606151715262.png)

------

## 49. FlashAttention 的 fusion

FlashAttention 还把多个操作融合到一个 kernel 中：

- QKᵀ；
- scale；
- mask；
- exp；
- softmax normalization；
- multiply V；
- output accumulation。

这样就避免了：

```
S 写回 HBM
P 写回 HBM
再读回来
```

中间结果尽量留在 SRAM / register 中。

这就是 operator fusion 的思想。

------

## 50. FlashAttention 的 recomputation

课件说 backward pass 没有展开，但提到 backward 会 tile-by-tile recompute。

普通 attention backward 如果保存完整 attention matrix，会消耗大量显存。

FlashAttention 的做法是：

> forward 不保存完整 attention matrix，backward 需要时重新按 tile 计算相关中间值。

这就是 recomputation。

它用更多计算换更少 memory。

由于 GPU 上计算相对便宜，HBM 访问相对昂贵，所以这是划算的。

------

## 51. FlashAttention 为什么快？

总结一下，FlashAttention 快的原因不是少算了很多 FLOPs。

它真正减少的是：

```
HBM read/write
```

标准 attention：

```
QK^T -> 写 S 到 HBM
softmax -> 写 P 到 HBM
P @ V -> 读 P
```

FlashAttention：

```
Q/K/V 分块读入 SRAM
tile 内计算 score
online softmax
直接累积 output
不 materialize 完整 S/P
```

所以它把 attention 从：

> HBM-heavy

变成：

> SRAM-friendly

这就是本节课前面所有知识点的综合应用。

# 全课最终总结

这节 Lecture 5 的核心可以总结成下面几层。

------

## 第一层：硬件 scaling 是 LLM scaling 的基础

LLM 能变大，不只是因为算法好，也因为 GPU 提供了巨大的并行算力。

但是传统单核性能 scaling 已经不够了，所以现代 AI 依赖的是：

- GPU；
- Tensor Core；
- 低精度；
- 多卡并行；
- 高性能 kernel。

------

## 第二层：GPU 是 throughput machine

GPU 不追求单线程最快，而追求大量线程总吞吐最大。

它适合：

- 规则计算；
- 大规模并行；
- 矩阵乘法；
- 连续内存访问。

它不喜欢：

- 复杂分支；
- 随机访问；
- 小 kernel 太多；
- 中间结果频繁写回 HBM；
- 维度不对齐。

------

## 第三层：现代 GPU 的主要瓶颈经常是 memory

虽然 GPU FLOPs 很高，但 memory bandwidth 没有同等速度增长。

所以很多 ML workload 的瓶颈是：

```
data movement
```

不是：

```
floating point computation
```

这就是为什么要理解 roofline model。

------

## 第四层：高性能 GPU 算法的核心技巧

这节课讲的优化技巧可以合并成一张表：

| 技巧               | 解决什么问题              | 核心思想                               |
| ------------------ | ------------------------- | -------------------------------------- |
| control divergence | warp 内分支导致线程空转   | 让同一 warp 尽量走同一路径             |
| low precision      | 数据太大、计算慢          | 用更少 bit，减少搬运，使用 Tensor Core |
| operator fusion    | 中间结果频繁写回 HBM      | 多个操作合成一个 kernel                |
| recomputation      | activation 占显存、读写贵 | backward 时重新算，用计算换内存        |
| coalescing         | 内存访问不连续            | 让 warp 内线程访问连续地址             |
| tiling             | global memory 重复读取    | tile 放入 shared memory 反复复用       |

------

## 第五层：FlashAttention 是这些技巧的综合案例

FlashAttention 使用：

- tiling：分块处理 Q/K/V；
- fusion：把 score、softmax、V 聚合融合；
- online softmax：分块也能算 exact softmax；
- recomputation：backward 不保存完整 attention matrix。

所以它是一个非常好的例子，说明：

> 大模型系统优化不是改数学公式，而是改计算和数据搬运方式。

------

# 你复习这节课时最应该记住的 10 句话

1. GPU 优化的是吞吐，不是单线程延迟。
2. GPU 适合大量线程执行相同指令。
3. 一个 warp 通常有 32 个线程，warp 内 divergence 会降低效率。
4. GPU 内存有层级，register/shared memory 比 HBM 快很多。
5. 现代 GPU 的计算能力增长快于内存带宽增长。
6. 很多 ML 操作慢，不是因为算得多，而是因为搬数据太多。
7. 低精度既减少数据搬运，又能使用 Tensor Core。
8. Fusion 的本质是避免中间结果反复写回 global memory。
9. Tiling 的本质是把数据搬到 shared memory 后重复使用。
10. FlashAttention 的本质是减少 HBM 访问，而不是近似 attention。
